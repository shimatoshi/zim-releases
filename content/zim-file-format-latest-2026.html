ZIMファイル形式の最新仕様と主要用途

openZIM / Kiwix のオフライン知識アーカイブを、2026年9月時点の仕様・実装・用途から整理

カテゴリ：コンピューティング / オフラインWeb更新：2026-09-30対象：実用〜技術
30秒要約

ZIMは「Webコンテンツを高圧縮・索引付きでオフライン配布するためのオープンなコンテナ形式」です。2026年時点でもフォーマットのmajor versionは6系で、現行libzimは6.1系のminor revisionを生成します。libzim自体のソフトウェア版は9.x系まで進んでいるため、両者を混同しないことが重要です。主用途はWikipedia等の大規模知識ベース、教育・医療・旅行情報、Stack ExchangeやGutenberg、動画・Webサイトのオフライン配布です。

最新版は？ — ZIM形式はmajor 6、現行生成系は6.1系

libzim 7.0.0以降はZIM minor 6.1を使い、libzim 9.1.0ではminor revisionが6.1.2へ更新されています。libzim 9.xという数字はライブラリの版です。詳細へ →

何が強み？ — 圧縮・ランダムアクセス・検索を1ファイルにまとめる

多数の記事や画像などをclusterへまとめて圧縮し、directory/indexから個別コンテンツへアクセスできます。全文検索用Xapian indexも格納できます。詳細へ →

主要用途は？ — Wikipediaだけではない

Wikimedia、Project Gutenberg、Stack Exchange、TED、教育教材、医療情報、旅行ガイド、Webサイト保存、LAN内オフライン配信などに使われています。詳細へ →

現在の圧縮は？ — Zstandardが中心

現行libzim writerの既定圧縮はZstdです。旧来のLZMA2を読める系統もありますが、writer側ではZstdが標準です。詳細へ →

注意 — 「更新可能なWebアーカイブ」ではない

ZIMは基本的にスナップショット配布向けで、Kiwix公式FAQでもincremental updateは現時点で提供されていません。更新時は通常、新しいZIMを再生成します。詳細へ →

最新バージョン：何を「バージョン」と呼ぶか

↑ 要約へ

ZIMファイル形式

major versionは6。 openZIMのreference implementationであるlibzimは、現在もmajor 6のZIMを生成します。libzim 7.0.0でminor 6.1へ移行し、libzim 9.1.0のChangeLogではminor revisionを6.1.2へ更新したと明記されています。

libzim

ライブラリの版は9.x系。 これはC++実装のソフトウェアバージョンであり、ZIMファイル形式が「v9」になった意味ではありません。

最も重要な区別

「libzim 9.x」≠「ZIM format v9」。ZIMヘッダのmajor/minorと、libzimのrelease versionは別の番号体系です。

内部構造：なぜ巨大な知識ベースを1ファイルにできるのか

↑ 要約へ

ZIMは単なるZIPのような「ファイル詰め合わせ」ではなく、Header、MIME type list、URL/title pointer、directory entries、clusters、checksum、必要に応じた検索indexを組み合わせたランダムアクセス向けアーカイブです。

要素役割
Headermagic、major/minor version、UUID、entry数・cluster数、各tableのoffsetなどを保持。
Directory entrypath/title、MIME type、redirectやcluster/blobへの参照など、個々の論理エントリを記録。
Cluster複数blobをまとめて格納・圧縮。HTMLや画像等を個別圧縮するより高い圧縮効率を狙える。
Indexタイトル検索・全文検索のためのデータ。libzimはXapian連携を持つ。

圧縮と検索

↑ 要約へ

現行libzim writerの既定圧縮はZstandard（Zstd）です。libzimのwriter APIでもdefault compressionがZstdとして定義されています。ZIMはcluster単位で圧縮するため、同種コンテンツをまとめることで圧縮効率とランダムアクセスのバランスを取っています。

検索は単純なファイル名検索に限定されず、ZIM内部へ全文検索indexを持たせられます。KiwixではZIMをローカルに置いたままタイトル検索・全文検索が可能です。

主要な用途

↑ 要約へ

1. 大規模百科事典・辞書

Wikipedia、Wiktionary、WikivoyageなどのWikimediaコンテンツを、画像や検索index込みでオフライン配布する用途が代表的です。

2. 教育・公共知識

回線が遅い・高価・不安定な学校や地域で、教材やリファレンスをUSB、SDカード、PCへ配布できます。

3. 専門資料

医学系Wikipedia（WikiMed）、Project Gutenberg、Stack Exchange、TEDなどのテーマ別知識アーカイブにも使われます。

4. 旅行・災害・現場用

ネット接続が期待できない移動中、遠隔地、災害時の予備情報源として有効です。

5. Webサイトのオフライン保存

Zimitは一般Webサイトをcrawlし、ZIMへパッケージします。Zimit 2.0では旧来より互換性が改善され、静的Wiki以外のWeb保存にも用途が広がっています。

6. LAN内オフライン配信

kiwix-serveでZIMをHTTP配信すれば、1台の端末やRaspberry Pi等からローカルネットワーク内の複数端末へ提供できます。

制約と現在の論点

↑ 要約へ
  • 基本はスナップショット。 Kiwix公式FAQではincremental updateは現在未提供です。
  • Webアプリ互換性はreader依存。 動的サイトや高度なJavaScriptは、生成方法とreader実装によって再現度が変わります。
  • 巨大ZIMは配布サイズが大きい。 その代わり、1回配布すれば通信なしで繰り返し利用できます。
  • 編集フォーマットではない。 ZIM内をその場で編集するより、原典・HTML・WARC等から再生成する運用が一般的です。

実用上の選び方

↑ 要約へ

「大量のWeb知識をオフラインで配る」ならZIMはかなり適しています。 とくに、HTML・画像・検索を1つの配布物にまとめたい場合に強みがあります。逆に、頻繁に差分更新するデータベース、共同編集、原データ解析が中心ならSQLite、Parquet、Git、WARC等のほうが扱いやすい場合があります。

今回のような研究記事・知識ノートをKiwixで読む用途では、自己完結HTML → ZIMは自然な構成です。画像やCSSを埋め込み、外部依存をなくしてからZIM化すれば、端末単体で安定して閲覧できます。
